变量更新规则:
  总则:
    - 变量只记录当前可变状态；背景资料、资料来源、角色知识矩阵、静态性格与关系史由世界书负责，不写入变量。
    - 只根据本轮正文中已经发生且有明确因果依据的事实更新。不得为了显得活跃而随机改变数值、关系或迷雾。
    - 每次回复都检查所有顶层对象；没有变化的类别只在 Analysis 写 no change，不生成无意义 Patch。
    - 主控身份（user 容器）开局采集后固定，聊天期间不得替换成另一名角色；五名核心角色（花奈、清寒、沉秋、楚羽笙、诺薇拉）的行固定存在，不得删除、不得改名。
    - 网名、化名、称呼变化只写入内容字段，不修改任何 record 键。
    - 数值仪表只表达叙事状态，不单独决定剧情走向或结果。

  Patch约定:
    - 只使用 add、replace、remove、move。
    - path 必须以 / 开头并严格对应中文变量路径。
    - add 用于新建对象、记录或数组项；新建 record 项时一次 add 完整对象。
    - replace 只用于已经存在的路径；不得对不存在的路径使用 replace。
    - remove 只用于确认存在且应清理的记录；move 只用于同一状态树内的结构调整。
    - JSON Pointer 中的 ~ 编码为 ~0，/ 编码为 ~1。
    - 数值必须写纯数字并保持在 schema 规定范围；禁止附加百分号或单位。

  初始化:
    - 当 /规则/初始化完成 为 false 时，在本轮回复的 UpdateVariable 中完成开局初始化；完成后将其 replace 为 true，此后不得重复初始化。
    - 初始化 user：从主控自捏信息与开局剧情采集姓名、DC网名、性别、年龄、身份、住址、来历、外貌等；未提供的字段保留"未知"，禁止猜测或伪造。
    - 初始化关系：好感度默认 50（线上普通群友基准），开局剧情或人设有明确依据时可在 40~60 内逐人校准；关系阶段一律为"线上群友"。
    - 迷雾全表保持"未揭示"，初始化时不得预翻任何格子。
    - 登场默认全部 false；仅当开局剧情确认主控与某人已在线下相遇才标记 true。
    - 初始化环境：日期、时段按开局设定填写；日期使用现实历法。
    - 此后 user 容器仍可随剧情用 replace 补充；关系、迷雾、登场走各自的常规规则。

  迷雾:
    - 结构为 知情者 → 事实ID → 知情状态。知情者稳定键：主控、花奈、清寒、沉秋、楚羽笙、诺薇拉，及后续新群员；事实ID 以迷雾事实注册表为准（H.家史、H.母亡、H.药、H.面具、H.轨迹、Q.保护色、Q.霸凌、Q.善良、Q.独居、C.背锅、C.社恐度、C.耳坠、C.未放弃、Y.父母、Y.安静、Y.草稿、Y.逃兵、N.拖延、N.才华、N.家庭群、N.延毕）。
    - 本人知晓自身事实是天然的，不入表：花奈的行不出现 H.* 格，清寒的行不出现 Q.* 格，依此类推。
    - 知情状态只有三种：未揭示、已揭示、误信已纠正。只有本轮正文出现明确的揭开场景（对上号、被目击、说漏、自曝、旧事被翻出等），才把实际获知者（含主控）的对应格翻为已揭示；主控行的翻转是门控与保密纪律的主要依据。
    - 一次场景揭开多个事实或多个知情者时，在同一 JSONPatch 数组中完成全部翻转。
    - 误信已纠正：仅当角色此前持有的表面误认被正文公开纠正时使用；没有纠正场景不得直接从"未揭示"改为此状态。
    - 揭示不回退：不得把已揭示或误信已纠正改回未揭示；回忆、闪回、他人转述不构成新揭示，除非正文明确本次获知。
    - 新群员加入时 add 完整的迷雾行，只写与当前剧情相关的格子，其余格子缺省视为未揭示。

  关系:
    - 结构为 角色 → { 好感度, 关系阶段 }。好感度范围 -100~100，负值表达敌意与决裂；50 为线上普通群友基准。
    - 只有明确的互动、事件或情感节点才能改变好感度；单次常规互动的变化保持克制。
    - 关系阶段参考阶梯：线上群友 → 线下相识 → 朋友 → 亲近 → 恋人；闹翻、决裂等特殊阶段依正文事实设定。
    - 攻略里程碑（识别、面具、树洞、摘耳机、南江话等）达成时同步更新关系阶段；阶段只前进，回退必须有正文依据的破裂事件。
    - 五人关系行永不删除；新群员初次线下登场时 add 完整关系对象。

  登场:
    - 结构为 角色 → boolean。仅当正文确认主控与该角色首次线下相遇时 replace 为 true。
    - 已遇标记不回退：再次见面、重逢不重复记初遇；线上线下身份对上号不改变此标记。
    - 新群员初次线下登场时 add 其登场键。

  任务:
    - 结构为 任务ID → { 状态, 进度备注 }。任务ID 使用稳定编号键；状态只允许 未接、进行中、完成、失败。
    - 进度备注只写当前阶段的简短结论，不写过程流水。
    - 任务清单位驱动后续登记；当前为空表，不得凭空新增任务。
    - 完成、失败后状态保留，不 remove；已接任务不得凭空消失。

  user:
    - 开局采集主控自捏信息；字段缺失保留"未知"，不得编造。
    - 后续剧情确认的新信息（住址、职业细节等）用 replace 更新对应字段。
    - user 不记录心情、资产、人际关系等状态，那些归各容器与世界书。

  环境:
    - 日期使用现实历法，时段只使用：黎明、清晨、上午、正午、下午、傍晚、夜间、深夜、凌晨、时段未详。
    - 时间只随剧情推进前进；回忆、闪回、电话与线上聊天不回拨环境。

  清理与不变量:
    - 五人固定行（关系、登场）与主控迷雾行永不删除。
    - 迷雾翻转不可逆；已遇标记不可逆；任务完成/失败态保留。
    - record 键一律使用稳定ID或规范短名（主控、花奈、清寒、沉秋、楚羽笙、诺薇拉）；显示名称变化不得破坏引用路径。
    - 不删除已揭示迷雾格、有效任务或 user 已采集字段。
    - 状态只存结论；不保存渲染文本、聊天记录副本或推导过程。
    - UpdateVariable 永远是每次回复的最后一个块。
