### 11.3 额外交叉核验里查出的两处

> 这两处不在 `技-1~技-12` 里，是核验时顺带对出来的。

#### ① 跃迁增幅与"点数"之间有一道除法（**建议驾驶员看一眼**）

`变量更新规则.txt` §一 的跃迁表给的是**战力增幅**：

| 跃迁类型 | 增幅 |
|---|---|
| 磨 | +50 |
| **逼** | **+90** |
| 悟 | +150 |

而同一节要求：「改 `/玩家/掌控度` 或 `/玩家/承载上限`（按突破方向选一个）」，然后「**重算并写入** `/玩家/基础战力`」。

问题在于 **每点 = 50 战力**，所以：

- 磨 +50 → **+1.0 点** ✅
- **逼 +90 → +1.8 点** ⚠️ 非整数
- 悟 +150 → **+3.0 点** ✅

**两个后果**：
1. 模型每轮要做一次 **÷50 的反算**——而模型不擅长算术，这正是当初要存一个 `基础战力` 字段的原因（`变量结构约束.js` 里写着「让模型每轮现算比存一个数更容易出错（模型不擅长算术）」）；
2. 「点」这个词（`骨架说明.md`：「每个点 = 50 战力」）会与实际出现的小数点不符。

**两条改法**：把增幅改成 50/100/150 的整数点组合，**或**把跃迁表直接写成「掌控度或承载上限 +1 / +1.8 / +3」。
> ⚠️ 但**数值本身可能属于第 05 阶冻结内容（`D-056` 只冻了"磨/逼/悟"的分段，没冻增幅数值）**——**要改请先回 `存档/第05阶` 核一遍**，Agent 不擅自改动。

#### ② 花奈档案里"一整档"的说法与规则差 50 分（低严重度）

| 出处 | 说法 |
|---|---|
| `设定/藤原花奈.txt` | 「内在损耗是分档的（**40–69 掉半档 / 70–89 掉一整档** / 90 以上基本不能战）」 |
| `变量更新规则.txt` §四 | 「损耗 40–69 → **−100** ／ 70–89 → **−250**」 |

位阶档位的间隔是 **200 分**，所以"半档" = 100 ✅ 对得上；但"**一整档**"应是 200，**规则里写的是 250**，差 50。

**不是错误，是措辞**——但这句话**会被模型抄进叙事**。
建议：把花奈档案那句改成「40–69 掉半档（−100）／ 70–89 掉到近乎一整档（−250）」，或统一口径。**由驾驶员定。**

### 11.4 一个静态查不出、必须真机的存疑点

`枚举字段()` 的实现是：

```js
z.string().transform(v => (选项.includes(v) ? v : 选项[0])).catch(选项[0]).prefault(选项[0])
```

`骨架说明.md` §六 记录过一个坑：「`.prefault()` 连着调两次——第二个静默失效（已全部改成只调一次）」。
但**这份说明没有记录"`.catch()` 之后再调 `.prefault()`"会怎样**——`prefault` 是 Zod v4 的方法，链在 `ZodCatch` 之后是否仍然生效，**静态读代码判断不了**。

| 项 | 内容 |
|---|---|
| 风险 | 若 `.prefault()` 在 `.catch()` 之后失效，枚举字段的**默认值会静默落空**（不报错，值与预期不符） |
| 影响面 | 全部**五类枚举字段**：身份记录 / 异化状态 / 血统认知 / 位阶（传闻·真实）/ 玩家已知程度 |
| 怎么验 | 真机新建一个空档，看五个枚举字段的初值是不是 `未登记 / 未涉足 / 未知 / 不入流 / 未知` |
| 归属 | **`验-N` 范畴，不是静态检查能解决的** |

> **Agent 标注**：这不是"发现了一个 bug"，是**发现了一条没人验证过的假设**。契约性写法（换成 `.catch()` 单独承担兜底、或在 transform 内部兜底）要不要改，**等真机结果**。

#### ① `位阶传闻` 这个字段，对五个人**全都无值可填**（**最要紧**）

`骨架/一致性检查清单.md` **角-6** 要求「位阶**分别写了传闻值与真实值**」，理由原文：「只写一个，你的『**实测数据会骗人**』就废了」（对应 `C-08` / `D-013`）。

| 藤原花奈 | **无**——没人拿她当战力单位 | 「对外说法＝**无**（没人把她当战力单位）；真实水平＝高位」 |

| **乙** | 不改 schema，只在 `变量更新规则.txt` 里写死一句：「**圈内没听说过他时，`位阶传闻` 填 `不入流`——此处 `不入流` 表示"圈内没有关于他的评价"**」 | **零代码改动**；但语义被扭曲成一词两义，而"一词两义"正是让模型写错数据的主要原因 |

> **Agent 的诚实意见**：这两条都有代价，**我不建议替主人选**。

#### ② `角-12` 五个人**系统性未满足**：没有任何一条"个人恩怨"

`角-12` 原文：「有**旧账**，且与某个**具体角色**挂钩——第 2 阶核心机制。**只有势力关系没有个人恩怨，NPC 会像阵营棋子**」。

核下来：

- 花奈：有旧账**事件**（当年替她背锅的人仍在圈里），但**没指名是谁** → ⚠️
- 清寒：有旧账**事件**（初中那个朋友），**没指名、且属前期纪律不得挖出** → ⚠️
- 羽笙：档案**明写"没有旧账"** → ❌
- 沉秋：旧账【待补】 → ❌
- 诺薇拉：旧账【待补】 → ❌

**五个核心角色之间，一条"个人恩怨"都没有**——现有的四条连接（沉秋→花奈、诺薇拉→花奈、清寒→花奈、羽笙→花奈）全是**指向关系**，不是**过节或交情**。

> **这不是"写漏了"，是"还没写得到"**——旧账要等对方存在才能咬合。花奈档案自己写着「作为可挂接的旧账钩子保留，**等后续角色出现时再决定要不要咬合**」。
> **但它有一个直接后果**：在世界书里，这五个人目前**互相之间没有私人理由**，只有功能性关系。**第一版剧情里若不补，他们真会像棋子。**

#### ③ `角-2`：鱼沉秋在形式上"不归位"

`角-2` 的不合格改法写的是「归位到**管理局 / 家族 / 散人网 / 不属任何一方**」——**四个选项里没有"外来势力"**。
而鱼沉秋属于**倒悬圣殿**（驾驶员确认的外来势力，**不占** `D-019` 的三足鼎立名额）。

> **这是设计如此，不是错误**——但它意味着 `角-2` 的选项列表**需要补一项**（"外来势力"或"以上皆非"），否则每次核验都会把她标成不合格。
> **建议**：把 `角-2` 的措辞改成「归位到四大块之一**或明确登记为外来势力**」。**待驾驶员定。**

#### ④ `角-17`／`角-5`／`角-9` 三处，沉秋与诺薇拉同时空

这三条不重复第十节的内容，但**放在一起看更有分量**：**"代价、觉醒刺激、武器"是一个角色的机制骨架**——它是"这个人为什么强、为什么痛、打起来什么样"。
沉秋和诺薇拉**这三样同时空着**，意味着：

> 她们现在**还不能进战斗**。一旦第一版剧情里让她们动手，模型只能现编——而 `骨架/变量更新规则.txt` 里那套战斗判定（§四）**需要这些值才能算**。

> **与第一版主线的交汇点**：**鱼沉秋是主梁上的"寻找者"。** 她是最可能先动手的那个人。**她的代价与武器，最好在写她的第 1 步之前定。**
