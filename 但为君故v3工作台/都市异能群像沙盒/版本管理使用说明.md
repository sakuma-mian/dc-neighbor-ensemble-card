# 版本管理使用说明（给你看的）

> 这份文件解释：**你不需要学 Git 命令**，只要对我说一句话就行。
> 建立日期：2026-08-18（第 4 阶 · 第 1 轮）

---

## 为什么给你建这个

你选了"**定期更新角色卡**、按剧情推进不断补充内容、安排结局并随版本更新推进"。

这意味着这个项目会活很久。而长期项目真正的敌人不是"做错"，是"**做错了回不去**"。三个具体场景：

| 场景 | 没有版本管理 | 有版本管理（现在这样） |
|---|---|---|
| 改了三个月，发现开场白被自己弄坏了 | 靠记忆往回翻，可能找不回来 | 一句话回到“开场白还好用的那个版本” |
| 玩家拿旧存档，你更新了剧情线 | 字段对不上，**存档错乱**，只能让玩家重开 | 有变更记录，能判断新内容跟老存档兼不兼容 |
| 想做 v2.0 的大改，但怕改烂 | 要么不敢改，要么改了回不去 | 先存一版，**放心改，改坏了退回来** |

**一句话概括**：它给的是"**随时能退回去**"这个能力。

## 你的常用操作（全部只需要说一句话）

| 你说 | 我会做 |
|---|---|
| "**存一版**" / "保存进度" | 把当前状态存档，附一句人话说明 |
| "**现在改了什么**" | 列出上次存档到现在改动的文件与内容摘要 |
| "**回到上一个版本**" | 回退到上一次存档的状态（**回退前我会先存当前状态**，所以回退本身也能撤销） |
| "**回到<某个版本>**" | 回到指定版本（比如"回到角色线和城市刚填好的那版"） |
| "**给这版打个标签，叫 v1.0**" | 给当前版本打上名字。**你要的"v0.5 更新"就靠这个实现** |
| "**列一下所有版本**" | 列出所有存档点、标签和说明 |

**你不需要记任何命令。**上面这些说法我会翻译成操作。

---

## 我会自动做的事

1. **每完成一个可验收的小块 → 自动存一版**，并写清"这次改了什么、为什么"；
2. **回退之前先备份当前状态**——所以"回退"这个动作本身也是可以再退回的，不会把你的东西弄丢；
3. **不做你没要求的事**：不推送到任何网站、不上传到任何地方、不发布。
   Git 现在是**纯本地**的，所有内容都只在你这台电脑的这个文件夹里。

## 技术备注（不用看懂，备查）

- 仓库位置：`D:\但为君故 v3 工作台\都市异能群像沙盒\`
- 隐藏了 `.git` 文件夹（Windows 隐藏属性），平时在资源管理器里看不到，不会干扰你；
- 行尾符设为不自动转换（`core.autocrlf=false`），避免中文文本和换行符被改动；
- 提交信息用 UTF-8 编码，中文说明不会变乱码；
- 仓库归属配的是 `Mocha <mocha@local>`（**没有改你的全局 Git 设置**）。
