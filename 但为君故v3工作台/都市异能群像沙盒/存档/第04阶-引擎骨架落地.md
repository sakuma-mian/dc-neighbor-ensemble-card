## 四、施工中修掉的两个问题（诚实登记）

### 问题 1：文件格式错误

第一次写"变量更新规则"时用了 `.md` 扩展名，但里面是 JavaScript 导出代码——**格式自相矛盾**。

**处理**：删除，重写为 `.txt` 纯文本（因为它是给模型看的正文，要能直接复制进世界书条目）。

### 问题 2：Zod 用法错误（这类错误不会报错，只会静默失效）

第一版 schema 里写了 `z.coerce.number().transform(...).prefault(x)`，又在外面套了 `.prefault(y)`——**第二个 prefault 无效**。

**原理**：`prefault()` 定义在 ZodEffects 上，调用后返回的是 `_ZodEffects` 实例，而它上面没有 `prefault` 方法。所以第二个调用不会报错，只会**静默不生效**。

**处理**：重写为 `数值字段(最小值, 最大值, 默认值)` 辅助函数，确保 prefault 只调一次。

**这个问题的价值**：它跟规范里警告的"跨 zod 实例导致 parse 静默产出 NaN"是同一类问题——**不报错但数据坏了**。所以我在骨架里把这条写成了注释，防止将来重踩。

## 五、刻意避开的做法（不拿驾驶员的项目去赌）

| 避开的东西 | 原因 |
|---|---|
| `<initvar>` | **两份权威规范都没有它的语法、触发时机、作用域定义**。只在"别删"的警告里出现过一次。规范不足，不用 |
| 事件名字符串硬编码 | MVU 事件名里**真有一个拼错的单词**（`mag_variable_initiailized`）。一律用常量引用 |
| 卡内自带 zod | 跨实例会让 `parse` 静默产出 NaN/undefined。只用酒馆助手注入的 `z` |
| 依赖未知的表达式或宏 | 规范明确"状态栏支持的表达式/宏"未提及。不用没验证过的写法 |
| 8 项实现悬案 | 规范标注为 medium 置信度，其中 P8 明确写"禁止基于此施工" |
