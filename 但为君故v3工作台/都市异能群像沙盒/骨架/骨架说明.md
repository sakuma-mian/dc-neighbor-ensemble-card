### MVU 是怎么接上的（2026-09-18 接线，五层）

变量系统不是一个零件，是**五层串起来**才转的。少任何一层，表现都是"没反应"，但原因完全不同——所以这一节值得记住：

| 层 | 在哪 | 本项目是哪个文件 |
|---|---|---|
| ① 变量本体 | 卡内脚本 | `mvu_加载器.js`（从 CDN 拉官方 `bundle.js`） |
| ② 结构约束 | 卡内脚本 | `变量结构约束.js`（Zod，拦非法值） |
| ③ 更新规则 | 世界书条目 | `[mvu_update]变量更新规则`（教模型怎么输出） |
| ④ 初始变量 | 世界书条目 | `[initvar]初始变量`（变量的出生证） |
| ⑤ 卡内正则（9 条） | 卡内正则（源文件 `骨架/正则脚本.mjs`） | **显示层 7 条**：状态记录面板（本轮说明／补丁／外壳／写入中／杂标签兜底）＋ 正文对话块（渲染／兜底）<br>**送模层 2 条**：旧楼层变量块不进提示词 ／ 状态栏占位符不进提示词 |

**接线前（2026-09-18 之前）的真实状态**：只有 ③ 和 ② 存在，而且 ③ 的名字写成了全角`【mvu_update】`、② 缺了它依赖的那一行来源——**所以这套变量系统一次都没有真正运行过**。

**两个容易忽略的硬前提**：
1. **卡必须有一条开场白**。MVU 在一条消息都没有时会直接中止（官方源码里写死的判断），提示"需要有开场白才能初始化变量"。
2. **世界书必须绑到卡上**。MVU 只扫**角色卡绑定的**世界书（主世界书＋附加世界书）；全局打开但没绑定的，它读不到——初始变量和更新规则都会落空。

### 正文格式（2026-09-18 定 · 驾驶员选「乙」案）

模型写到有人说话时，把**说出口的那句话**用标记包起来：

```text
藤原花奈合上账本，抬眼看你。<d s="花奈">你找谁？</d>
```

规矩写在世界书条目 `【常驻】正文格式 · 对话标记` 里（模型每轮都读得到）。**改这一条要同时改 `正则脚本.mjs` 里的「正文对话块」**——一个教模型怎么写、一个负责渲染，是一对。

**为什么值得这么做**：这是群像卡，最要紧的信息是"这句话谁说的"。不贴标记的话，界面上分不出说话人，心声和叙述也糊在一起。

**三条护栏（都在正则里，不用你操心）**：
1. 写歪的标记（少引号、拼错名字、忘了闭合）会被**兜底正则**扫掉，只留文字——绝不会把版面搞崩；
2. 标准写法渲染成左侧带竖线的对话块，**不覆盖主题配色**，深色浅色主题下都成立；
3. 变量块渲染成可展开的「状态记录」面板，默认收起，想看再点开。

**想先看看效果**：跑 `node 骨架/验证正则.mjs`。它会拿一条模拟回复把全部正则真跑一遍，把"玩家看到的"和"模型收到的"都打印出来。


### 关于世界书（2026-09-18 新增）

**世界书是"按关键词触发注入"的设定集**——模型不是一次看到全部设定，而是提到谁/哪儿，才把那一块给它。

**怎么用**：改 `生成世界书.mjs` 里的条目 → 跑 `node 骨架/生成世界书.mjs` → 它会把 `但为君故V3.json` 与 `世界书条目总表.md` 重写一遍 → 在 SillyTavern 里**导入世界书**，选 `但为君故V3.json`（导入后世界书的名字就是文件名）。

**三条已经写进生成器、不用你操心的纪律**：
1. **中文必须关掉「全词匹配」**——它按空格边界判断单词，中文没空格，会把关键词匹配打死。生成器给每条都写了 `matchWholeWords:false`；**另外 SillyTavern 全局设置里也有一项同名开关，导入后请一并关掉并重启**。
2. **常驻条目（🔵）每轮都进提示词**，所以只有"必须每轮在场"的东西才是常驻——目前只有四条。
3. **秘密不进世界书**。伏笔一律只写"这件事存在但不可说"（见常驻条目「前期封锁线」），**不写内容**——否则模型每轮都拿着它，迟早说漏。


### （承接上表）关于 `初始变量.json` 的三条注意事项

1. **它必须是"纯 JSON"**——不能有注释、不能有尾逗号，也**不要往里加 `_说明` 这类注释键**。
   原因：变量文件里的每个键都会被当成**真实变量字段**读进去，元信息混进去就会变成垃圾数据（这一条是我在自检时发现并修掉的）。
2. **字段格式是"路径直接指向值"**——不要写成 `[值, 说明]` 这种二元组，那种旧格式已经废弃。
3. **改动它的结构时，记得把 `/世界/变量结构版本` +1**——否则老玩家的存档会缺字段而错乱。

## 三、你现在要做什么（三件事）

### 第 1 件：按城市模板填城市
文件：`设定/城市模板.md`

**特别提醒**：城市的"关键地点"和"开局时间点"**必须填**，因为开局匹配算法要用（它靠"常驻地点"算你最先遇到谁）。

### 第 2 件：按角色模板填 7 个核心角色
文件：`设定/角色模板.md`（复制 7 份，每份一个角色）

**每个角色必填**：常驻地点、日常身份、性格、血统、觉醒刺激、能力本质、代价、位阶（传闻 + 真实）、目标、底牌、旧账。

### 第 3 件：按故事线模板填 7 条故事线
文件：`骨架/故事线模板.md`（复制 7 份）

**每条线最容易被漏掉的三项**（漏了就装不进机制）：
1. **他缺什么** —— 这是玩家能介入的唯一入口；
2. **涟漪出口** —— 这条线会影响到谁；
3. **玩家拒绝后会怎样** —— 拒绝不能导致卡住。

## 四、变量是什么（大白话）

变量就是**这张卡的记忆**。模型自己不记事，聊到第 50 楼会把设定记混——变量是它唯一可靠的事实来源。

**三层，一共 58 个字段：**

### 第一层：玩家自己（11 个）

| 记什么 | 大白话 |
|---|---|
| 能力本质 | 你觉醒的是什么能力（**定了就不改了**） |
| 掌控度 / 承载上限 | 用得有多精细 / 能压多大（0–10，**每个点 = 50 战力**） |
| **基础战力** | **你有多强**（0–1300，由上面两项算出来，只在跃迁时才变） |
| 内在损耗 | 你被掏空到什么程度（用能力会涨，休息会降） |
| 暴露程度 | 你出手被同类感应到的风险（会涨，也会落） |
| 身份记录 | 你在官方档案里是什么人：**未登记 / 被登记 / 被通缉**（不会自己回落） |
| 异化状态 | 有没有走那条危险路线 |
| 血统认知 | 你对自己出身的了解 |
| 当前状态 | 临时状态，过期就删 |
| 圈内代号 | **别人给你起的名字**，开局是空的 |

> **第 5 阶新增了两个东西**：
> 1. **基础战力**（新字段）——你有多强，只有你能看见这个数字；
> 2. **掌控度／承载上限的取值范围从 0–5 扩到 0–10**——一格从 5 分变成 50 分，
>    这样"练出半级"能被看得见，成长才有感。

### 战力系统一句话版（第 5 阶冻结）

> **你有多强（基础战力）→ 圈内以为你多强（位阶黑话）→ 这一场你打成什么样（当轮战力，不记档）。**
>
> - 数字**只有你自己看得见**；别人你只能靠感应和交手去猜，而且**猜不出他的能力是什么**；
> - 变强不是靠攒，是靠**事件跳**：平时不涨，只在"磨／逼／悟"三种情况下跳一次，每次都要付代价；
> - 战斗不掷骰子：差 200 分以上是碾压，差 50 以内才是同档缠斗；**想跨 200 分赢，必须有事件解释**。

**完整设计在 `存档/第05阶-战力与战斗评定.md`**——包括打分公式、成长闸门、武器三类用法、缴械、感应读数、战斗评定五步。

### 第二层：7 个核心角色（每个 8 个字段）

**最关键的是"位阶三件套"**：

| 记什么 | 大白话 |
|---|---|
| 位阶传闻 | 圈内**以为**他什么水平（可以不准） |
| 位阶真实 | 他**实际**什么水平 |
| 玩家已知程度 | **你到底知不知道**：未知 / 有传闻 / 已确认 |

**为什么三个都要有**：只记一个，你定的"实测数据会骗人"就废了；不记第三个，模型每轮都会忘记你知不知道——那"验证对方底牌"这个玩法就没了。

另外记：故事线进度、与玩家的账（标签，不是好感度）、被掌握的底牌、圈内代号、是否已接触。

> **第 5 阶补充（2026-09-16）**：位阶那两个字段**同时就是战力系统的"对外读数／真实档位"**。
> 圈内怎么评他、他实际多强——战力系统不再另开一套字段，直接读这两个。
> 这就是"战斗力"和"名声"能同时成立、又不会各说各话的原因。

### 第三层：世界（6 个字段）

日期、事件线（只记结果）、四个势力的状态、当前引力源（谁在找你）、结局进度、变量结构版本。

**其中"变量结构版本"只有脚本能写。** 它是为你长期更新卡准备的——将来你加字段时，脚本靠它判断要不要给老玩家的存档补默认值。

## 五、为什么变量不记这三样

| 不记 | 理由 |
|---|---|
| NPC 当前在哪 | **最容易过期**——记了他在城东，你下一步把他叫到城西，数据就废了。位置由故事线进度推导 |
| 好感度数值 | "欠他一次"比"好感度 73"信息量大得多，模型也更不容易用错 |
| 角色的内心想法 | 那是人设层的东西，不属于状态 |

**每条字段都能指回一条已冻结的决定**——完整对应表在 `存档/第04阶-首版范围与交付物.md`。这是防止变量表膨胀的闸门。

## 六、技术上的坑（已经避开，但你要知道）

这些是规范里明确记载的，写在这里免得将来有人重踩：

| 坑 | 后果 | 现在的处理 |
|---|---|---|
| 卡内自己引第三份 zod | **静默产出 NaN / undefined**，不报错但数据全坏 | 只用酒馆助手注入的 `z`，不 import |
| 「事件名里有个拼错的单词」 | **2026-09-18 更正：这条记录方向搞反了。** 从官方 `bundle.js` 里读出来的常量是 `mag_variable_initialized`（**单 i，拼写正确**）；双 i 的 `initiailized` 只出现在酒馆助手的 `.d.ts` 类型文件里。**错的是类型声明，不是运行时。** | 仍然用常量引用（好习惯）；但**排查"事件不触发"时不要再往拼写方向查**——手打正确拼写是能用的 |
| MVU 的两个标记必须用**半角**方括号 | 写成全角`【initvar】`／`【mvu_update】`，本体**认不出来**，而且**不报错**——表现只是"变量没反应" | 生成器里已锁成半角。这是 2026-09-18 查出的真实缺陷（原先 `[mvu_update]` 就是全角） |
| `.prefault()` 连着调两次 | 第二个**静默失效** | 已全部改成只调一次 |
| 自定义 XML 标签会**炸版面** | 酒馆已知 bug（Issue #3996）：`<UpdateVariable>`、`<d>` 这类没被声明过的标签，会被当成 `HTMLUnknownElement`，叠上 Showdown 的换行处理 → `<br>` 双份堆叠，**版面不是难看，是直接崩** | 所有自定义标签都必须被正则**抢在 showdown 之前**消费掉。这就是第 ⑤ 层正则存在的真正原因——它首先是护栏，其次才是美化 |
| 事件线数组无限增长 | 提示词悄悄膨胀 | 已设上限（保留最近 12 条） |
