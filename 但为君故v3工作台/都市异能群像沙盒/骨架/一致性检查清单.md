# 一致性检查清单

> **用途**：你交付城市 / 角色 / 故事线之后，我按这份清单逐条核验，指出与已冻结设定的冲突。
> **怎么用**：每条都写明了"检查什么、为什么、不合格时怎么改"。
> **重要说明**：这份清单上的检查是**静态检查**——它只能证明"内容与设定不冲突"，**不能证明卡能跑**。能跑只能在真实 SillyTavern 里验。
> 建立日期：2026-08-18（第 4 阶）

---

## 一、城市检查

| # | 检查项 | 为什么 | 不合格怎么办 |
|---|---|---|---|
| 城-1 | 城市整体上不知道异能存在；异常只停留在都市传说层面 | C-01 隐世前提。一旦变成"公开的秘密"，整个世界观的压迫感基础就塌了 | 收窄知情范围，或降级为"零星传闻" |
| 城-2 | 人口在千万量级 | C-03 几百人的比例要靠大基数才说得通 | 调整人口数字，或重算异能者数量 |
| 城-3 | 有**具体**的"关键地点"，且写明"在那儿能发生什么" | 开局匹配算法要用地点，纯背景板算不出来 | 补 6–10 个可发生事件的地点 |
| 城-4 | 没有设置"用异能会被摄像头/仪器拍到"这类物理痕迹机制 | C-11 物理痕迹机制**在本设定中已被排除**。加了它，DNA 就变成另一张卡 | 移除物理痕迹，或明确登记为"重大变更"并重新讨论 |
| 城-5 | 管理局的据点有正当外壳（明面挂什么牌子） | D-022 半官方：明面执法，暗地有算盘 | 补一个对外身份 |
| 城-6 | 三个大族 + 一个没落旧家都有落脚处，且**看得出谁是没落的那家** | D-025 三强一弱 | 给旧家一个"落魄但知道很多"的处境 |
| 城-7 | 圈内黑话有实际使用场景 | D-026 真名 + 圈内代号。黑话没有使用场合就是摆设 | 写明他们在哪些场合说黑话、怎么在普通人面前掩饰 |
| 城-8 | 写了"开局时间点"与"最近的**大事**" | 让世界有一个正在运转的起点；也是开局匹配的输入 | 补日期与一件近期事件 |

## 二、角色检查（每个核心角色逐条过）

| # | 检查项 | 为什么 | 不合格怎么办 |
|---|---|---|---|
| 角-1 | 有真名**也有**圈内代号 | D-026。真名是"他是谁"，代号是"大家以为他是谁" | 补代号；注意代号应像别人给起的，不像自我介绍 |
| 角-2 | 明确属于四大块之一并注明内部立场 | D-019 / D-022 / D-025 | 归位到管理局 / 家族 / 散人网 / 不属任何一方 |
| 角-3 | **能力本质固定**，不会突然长出第二个能力 | C-06。能力漂移会让 NPC 底牌失效，所有"算计"变成模型现编 | 把新增的能力改成"同一能力的新用法" |
| 角-4 | 成长只走两条路：提升掌控度/承载上限，或走异化路线 | C-06 / D-011 | 删掉"突然变强""血脉觉醒出新能力"这类写法 |
| 角-5 | **代价同时包含**："伤自己"和"增加暴露" | C-07 内外双收。只写一层就是没写完 | 补上缺失的那一层 |
| 角-6 | 位阶**分别写了传闻值与真实值** | C-08 / D-013。只写一个，你的"实测数据会骗人"就废了 | 补上另一份 |
| 角-7 | 明确标注**是否藏级** | D-013 藏级是常规手段。默认大多数人不会公开真实水平 | 补标注 |
| 角-8 | 血统背景写清（名门/旁支/平民/不明），且**不能靠血统认人** | C-04 / C-05。高血统者觉醒前与普通人无异 | 删掉"一看就是世家子弟"这类外显描写 |
| 角-9 | 有**觉醒刺激**，且它是真正"极致"的 | C-04。最优秀的异能者往往是被毁得最彻底的那个 | 补刺激；避免"睡一觉就觉醒了" |
| 角-10 | 有**站得住的理由** | C-10 灰色基调的一半 | 补：他为什么这么做，玩家听完能理解 |
| 角-11 | 有**不可原谅的事** | C-10 的另一半。没有这半，角色会变成好人卡 | 补一件他手上真的脏的事 |
| 角-12 | 有**旧账**，且与某个具体角色挂钩 | 第 2 阶核心机制。只有势力关系没有个人恩怨，NPC 会像阵营棋子 | 补旧账，并注明对方是谁 |
| 角-13 | 有**常驻地点**与**日常身份** | 开局匹配算法的输入。缺了它，算不出玩家会遇到谁 | 补这两项 |
| 角-14 | 有目标、底牌、把柄 | 目标决定他会不会自己动；底牌是算计的筹码 | 补齐 |
| 角-15 | 属于"核心 6–8 人"的**唯一 7 个位置**之一，且功能不重复 | D-020。两个人功能重复 = 其中一个是多余的 | 合并，或给其中一个不同的内部立场 |

## 三、故事线检查（每条线逐条过）

| # | 检查项 | 为什么 | 不合格怎么办 |
|---|---|---|---|
| 线-1 | 写得清 **"他缺什么"** | 这是玩家能介入的**唯一入口**。没有缺口，玩家只能旁观 | 补缺口，并确认玩家手上可能有他缺的东西 |
| 线-2 | 每个阶段都有**玩家介入的两种走向**（介入 / 不介入） | D-035 引力而非轨道。两种走向结果一样，玩家的选择就是假的 | 补第二种走向 |
| 线-3 | 每个阶段都有**涟漪出口** | D-033 涟漪式交织。没有涟漪，八条线就是八个独立剧情 | 补：这一步会影响到谁、影响什么 |
| 线-4 | 写了**玩家拒绝后会怎样**，且不导致卡住 | D-035。拒绝不能阻塞，引力应转向别处 | 补一条转向路径 |
| 线-5 | 写了**自主行动性**（玩家完全不介入能走到哪一步） | D-002 真群像的底线。答"原地不动"= 这个 NPC 是功能件 | 补 NPC 自己会推进到哪一步 |
| 线-6 | **引力理由是剧情内理由**，不是系统指派 | D-035。出现"系统提示""任务"就破坏沙盒感 | 改成"他需要你 / 他查到你的底 / 他感应到你了" |
| 线-7 | 交汇点已与对方那条线**双向核验** | 单向写的交汇，在对方线里可能对不上 | 回头检查对方的文件 |
| 线-8 | 涉及的变量字段**都存在于骨架中**，没有自造字段 | 自造字段不会被 schema 认可，写入会失败或丢失 | 对照 `骨架/变量结构约束.js` |
| 线-9 | 与既有事件线不冲突（时序自洽） | 第 1 阶检查里标记的风险：两条线互相矛盾会让玩家察觉世界是假的 | 对齐时序，或合并为同一事件 |
| 线-10 | 有**终点状态**，且写明"世界因此变了" | D-032 串珠式：线走完要能产生下一次引力的来源 | 补终点与涟漪落点 |

## 四、机制检查（全局）

| # | 检查项 | 为什么 |
|---|---|---|
| 机-1 | "极少数异化者"的**数量在 3–5 人区间** | 几百人的密度下，"极少数"的实际含义就是这个量级；人多了世界会失衡 |
| 机-2 | 核心 7 人的势力分布**均衡**（三势力各 2 + 中立 1） | 每个势力都要能自己往前走；单势力只有一人时产生不了内部张力 |
| 机-3 | 至少有一条线的**涟漪出口指向世界层面**（进 `/世界/事件线`） | 否则世界层永远不会变化，"伪流动"看不出来 |
| 机-4 | 开局匹配选的第一个接触者，理由**能一句话说清** | 说不清理由的开局会被玩家感觉成随机安排 |
| 机-5 | 每个核心角色的"故事线进度"取值**互不混淆** | 进度值是变量里的字符串，混了就没法判断走到哪一步 |

## 五、技术检查

| # | 检查项 | 为什么 |
|---|---|---|
| 技-1 | 卡内代码**只用酒馆助手注入的 `z`**，绝不自带 zod | 跨实例会让 `parse` **静默产出 NaN/undefined**——不报错，数据全坏 |
| 技-2 | 所有事件名用**常量引用**，没有手打的字符串 | MVU 事件名里真有一个拼错的单词（`initiailized`），手打必错 |
| 技-3 | `.prefault()` **不连调两次** | 第二个会静默失效（已修过一次，需复查新增代码） |
| 技-4 | 会增长的数组都**设了上限** | 事件线这类数组无限增长是提示词悄悄膨胀的主因 |
| 技-5 | 新增字段时**同步更新变量结构版本号** | 否则老玩家的存档会缺字段而错乱（D-037 长期更新的前提） |
| 技-6 | 每个变量**只有一个写者**（模型或脚本，不混） | 规范铁律：不能让模型和脚本抢同一个字段 |
| 技-7 | `registerMvuSchema` 在 `$()` 回调中调用 | 需要等 DOM 就绪，模块顶层直调会失败 |
| 技-8 | 开局页**不在预览阶段写正式变量** | 规范禁令：预览阶段禁止写 MVU 正式变量，否则取消开局会留下半套状态 |

## 六、验证检查（真机）

> 以下全部**必须**在真实 SillyTavern 里完成。静态检查通过不算完成。

| # | 检查项 | 验收方式 |
|---|---|---|
| 验-1 | 开页 → 改草稿 → 刷新恢复 → 确认 → 真实玩家楼 → 真实 AI 楼 → 变量初始化 | 走完完整链路（规范原文的稳定完成门） |
| 验-2 | 模型能稳定输出合法的 JSONPatch | 观察若干轮，看有没有非法操作或路径错误 |
| 验-3 | 位阶三件套真的被分别维护 | 检查"玩家已知程度"有没有随着验证行为正确提升 |
| 验-4 | 暴露程度会涨也会落 | 用能力后上升，过一段时间/休息后下降 |
| 验-5 | 切聊天不串档 | 开两个聊天，确认草稿与变量互不污染 |
| 验-6 | 重复提交不会出问题 | 反复点确认，确认不会产生两条开局消息 |
| 验-7 | 断网时不崩 | 断网后确认降级行为可接受 |
| 验-8 | 手机端可用（如果是目标平台之一） | 软键盘、横屏、长正文 |
| 验-9 | 你的真实 ST 版本与酒馆助手版本 | 记录实际版本号——**规范里的版本快照不是要求，只是取材时的情况** |

## 七、每次核验的输出格式

我核验后会给你：

1. **通过项**：列出通过哪些检查；
2. **冲突项**：具体哪条不合格、冲突的是哪一条已冻结决定、原文怎么写的；
3. **建议改法**：给出可选方案与各自代价（由你决定，不替你改）；
4. **不确定项**：明确列出我判断不了的地方，以及需要什么才能判断；
5. **未验证项**：明确说明哪些只能等真机。

**我不会做的事**：不替你改内容、不因为"看起来差不多"就放行、不把静态检查说成能跑。
