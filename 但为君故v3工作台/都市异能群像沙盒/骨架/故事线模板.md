# 故事线模板（复制这份来填）

> **用法**：复制本文件，改名成 `<角色名>-故事线.md`，逐项填写。
> **字段含义与硬性要求**：见同目录 `故事线容器格式.md`——那里解释了每个字段为什么必须填。
> **谁填**：驾驶员。Agent 负责检验（对照第 1~3 阶的施工条款）与落地到卡。
> 建立日期：2026-08-18

---

| 字段 | 填写 |

## 起点状态

| 字段 | 填写 | 提醒 |
|---|---|---|
| 他在做什么 | | 故事开始时，他手上正在忙的事 |
| 他想要什么 | | 一句话能说清 |
| **他缺什么** | | **必填。这是玩家能介入的唯一入口**——没有缺口，玩家只能旁观 |

---

## 玩家的位置

| 字段 | 填写 | 提醒 |
|---|---|---|
| **玩家如何进入这条线** | | |
| **引力理由** | | **必须是剧情内理由**（他查到你的底、他需要你、感应到你了……），不能是"系统指派" |
| **玩家拒绝后会怎样** | | **必填。拒绝不能导致卡住**——引力应该转向别的线 |

---

## 自主性与约束

| 字段 | 填写 | 提醒 |
|---|---|---|
| **自主行动性** | | **必填。玩家完全不介入时，这条线自己能走到哪一步？** 答"原地不动"= 这个 NPC 不是活人 |
| 时间跨度 | | 推进需要多少天 |
| 是否可逆 | | 走完后能反悔吗 |

---

## 自查清单（填完逐条打勾）

- [ ] 角色真名与变量 key 一致
- [ ] **他缺什么** 写清楚了，且玩家手上可能有他缺的东西
- [ ] 每个阶段的"玩家介入的走向"至少 2 种
- [ ] 每个阶段都有"涟漪出口"
- [ ] 写了"玩家拒绝后会怎样"，且不导致卡住
- [ ] 写了"自主行动性"
- [ ] "引力理由"是剧情内理由
- [ ] 涉及的变量字段都在骨架里存在（对照 `骨架/变量结构约束.js`），没有自造字段
- [ ] 交汇点已与对方那条线双向核验

---

## 交给 Agent 检验时，请说明

1. 这条线你希望它**优先服务什么**（人物弧光 / 世界推进 / 给玩家提供选择）；
2. 有没有**必须保留**的元素（不能改的部分）；
3. 有没有**你不确定**的地方（希望我重点看的地方）。
