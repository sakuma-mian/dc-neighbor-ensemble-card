# 故事线容器格式

> **这份文件是格式规范，不是内容。** 它规定"一条角色故事线该长什么样"、有哪些字段、怎么和其他线交汇。
> 剧情由驾驶员提供；Agent 只负责让剧情装得进这套机制、并检验它与已冻结设定是否冲突。
> 建立日期：2026-08-18（第 4 阶）

---

## 一、为什么需要"容器"

第 3 阶冻结了叙事结构：**串珠式**（一扇门接一扇门）+ **涟漪式交织** + **引力而非轨道**。

这三条要能跑起来，每条角色线就必须满足一组**结构条件**——否则会出现这些翻车方式：

| 翻车方式 | 后果 |
|---|---|
| 故事线没有"启动条件" | 玩家不知道什么情况下这条线会开始，线永远不启动 |
| 故事线没有"玩家可介入的节点" | 玩家插不进去，只能看 NPC 自己演 |
| 故事线没有"涟漪出口" | 一条线走完对世界毫无影响，"交织"变成空话 |
| 故事线没有"推进触发条件" | 模型不知道什么时候该往前推，线会卡住或乱跳 |
| 故事线没有"结局状态" | 线走完后 NPC 不知道该怎么继续存在 |

**容器的作用就是把这五种漏洞堵住。**

## 二、一条故事线的结构（必填字段）

```yaml
# ===== 基本信息 =====
角色: <真名>                    # 必须是 /角色/ 变量里的同一个 key
代号: <圈内代号>
所属势力: 管理局 | 家族 | 散人网 | 不属任何一方
故事线名: <一句话概括这条线，例如"被抹掉的档案">

# ===== 起点与终点 =====
起点状态:                       # 这条线开始时，他处在什么状态
  他在做什么:
  他想要什么:
  他缺什么:                     # 关键：他缺的东西，就是玩家能介入的地方

终点状态:                       # 这条线走完后，他会变成什么样
  他变成了:
  世界因此变了:                 # 涟漪的落点（必须写）
  他对玩家的态度:

# ===== 阶段（建议 3–5 个）=====
阶段:
  - 标记: 第1步：<一句话>
    触发条件:                   # 什么情况下进入这一步
    他会做什么:
    玩家可介入的节点:            # 玩家在哪些时刻可以插手
    玩家介入的不同走向:          # 至少 2 种（介入 / 不介入）
    涟漪出口:                   # 这一步会影响到谁、影响什么
    涉及的变量字段:              # 对应 /角色/{真名}/故事线进度 的取值

  - 标记: 第2步：<同上>
    ...

# ===== 交汇点 =====
与其他线的交汇:
  - 对方角色: <真名>
    交汇方式: 直接冲突 | 因果关联 | 间接影响
    交汇发生在: <哪一步>
    交汇后两边各自会怎样:

# ===== 玩家的位置 =====
玩家如何进入这条线:              # 对应开局匹配或后续引力
引力理由:                       # 他为什么找玩家（必须是剧情内理由，不能是系统指派）
玩家拒绝后会怎样:                # 必须写。拒绝不能导致卡住

# ===== 约束检查 =====
自主行动性:                      # 玩家完全不介入时，这条线自己能走到哪一步？
时间跨度:                        # 推进所需的时间
是否可逆:                        # 走完后能反悔吗
```

## 三、硬性要求（不满足的线不能进卡）

### 要求 1：必须有"他缺什么"

**没有缺口，玩家就没有介入的理由。**这条线会变成玩家只能旁观的独角戏。

**检验方法**：把"他缺什么"这一行遮住，问自己——玩家为什么非要跟他打交道？答不上来就是不合格。

### 要求 2：每个阶段必须有"玩家介入的不同走向"

至少两种：**介入**与**不介入**。

**为什么**：这是"引力而非轨道"（D-035）的落地形式。如果玩家介入与不介入结果一样，那玩家的选择是假的。

### 要求 3：每个阶段必须有"涟漪出口"

必须写明这一步会**影响到谁、影响什么**。

**为什么**：这是"涟漪式交织"（D-033）的落地形式。没有涟漪出口，八条线就是八个独立剧情，世界不会显得在自转。

### 要求 4：必须有"玩家拒绝后会怎样"

**拒绝不能导致卡住。**玩家拒绝了这条线，引力应该转向别的线，而不是原地等待。

### 要求 5：必须能"自主行动"

写明"玩家完全不介入时，这条线自己能走到哪一步"。

**为什么**：这是"真群像"（D-002）的底线。如果一个 NPC 不推动就完全静止，他不是活人，是功能件。

### 要求 6：涉及变量时必须对得上

"涉及的变量字段"必须与骨架里的字段一致（见 `骨架/变量结构约束.js`），不能自己发明字段名。

## 四、与其他机制接口

| 机制 | 接口位置 | 说明 |
|---|---|---|
| **开局匹配** | `起点状态` + `角色人设的常驻地点/职业/性格` | 匹配算法读这两处，算出谁先接触玩家（见 `骨架/开局匹配规则.md`） |
| **故事线进度** | `阶段[].标记` | 每个标记会成为 `/角色/{真名}/故事线进度` 的一个取值 |
| **世界时钟** | `时间跨度` | 推进时更新 `/世界/日期` |
| **事件线** | `涟漪出口` | 涟漪产生的结果写进 `/世界/事件线`（只记结果） |
| **引力源** | `引力理由` + `起点状态.他缺什么` | 写进 `/世界/当前引力源` |
| **位阶三件套** | 角色人设里的位阶设定 | 走线过程中提升 `/角色/{真名}/玩家已知程度` |
| **结局进度** | `终点状态` | 关联 `/世界/结局进度` |

## 五、检验清单（每条线写完后逐条核）

- [ ] `角色` 的 key 和变量里的真名完全一致
- [ ] `他缺什么` 写清楚了，且玩家手上可能有他缺的东西
- [ ] 每个阶段的 `玩家可介入的不同走向` 至少 2 种
- [ ] 每个阶段的 `涟漪出口` 都写明了影响到谁
- [ ] 写了 `玩家拒绝后会怎样`，且不导致卡住
- [ ] 写了 `自主行动性`（玩家完全不介入能走到哪）
- [ ] `引力理由` 是剧情内理由，不是"系统指派"
- [ ] 涉及的变量字段全部存在于骨架中，没有自造字段
- [ ] 与其他线的交汇写清楚了，且对方那条线上也能对上（**双向核验**）
