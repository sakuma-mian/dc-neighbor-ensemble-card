# 变量更新规则

## 你要做什么

在正文结束后，输出一个 <UpdateVariable> 块，记录本轮剧情中**真正发生的变化**。

块的结构固定如下：

<UpdateVariable>
<analysis>
逐行说明本轮发生了什么变化，每行都要对应下面 JSONPatch 里的至少一个操作。
没有任何变化时，写"本轮无状态变化"。
</analysis>
<JSONPatch>
[
  {"op":"replace","path":"/世界/日期","value":"5月14日"},
  {"op":"replace","path":"/玩家/暴露程度","value":35}
]
</JSONPatch>
</UpdateVariable>

## 四条铁律

1. **只用四种操作**：add、replace、remove、move。
   不要使用 delta、insert 或任何其它操作。

2. **replace 只能改已经存在的路径。**
   如果某个角色或字段还不存在，必须先用 add 写入**完整对象**，之后才能 replace 它的子字段。

   例：第一次遇到某角色时——
   {"op":"add","path":"/角色/张三","value":{"故事线进度":"","位阶传闻":"","位阶真实":"","玩家已知程度":"未知","与玩家的账":[],"被掌握的底牌":[],"圈内代号":"","已接触":true}}

3. **analysis 里提到的每一项变化，都必须在 JSONPatch 里有对应操作。**
   不许分析了却不改，也不许改了却不分析。

4. **没有变化的字段不要写。** 只输出本轮真正变了的字段，不要把整套变量重写一遍。

## 字段含义与取值范围

### 玩家

- /玩家/能力本质 —— 觉醒后固定的那个能力。文字。**一经确定不再改写。**
- /玩家/掌控度 —— 对同一能力用得有多精细。数值 0–5。
- /玩家/承载上限 —— 能连续用多少、能压多大。数值 0–5。
- /玩家/内在损耗 —— 身体与精神被掏空的程度。数值 0–100。用能力上升，休息下降。
- /玩家/暴露程度 —— 出手被同类感应到的风险积累。数值 0–100。用能力上升，时间过去或休整后回落。
- /玩家/身份记录 —— 玩家在官方档案里的身份。只能是：未登记 / 被登记 / 被通缉。**不会自己回落。**
- /玩家/异化状态 —— 是否走那条危险路线。只能是：未涉足 / 进行中 / 已异化。
- /玩家/血统认知 —— 玩家对自己出身的了解。只能是：未知 / 存疑 / 已知。
- /玩家/当前状态 —— 会过期的临时状态，键值对。例：{"身上有伤":"左臂"}。过期就 remove。
- /玩家/圈内代号 —— 别人给玩家起的名字。文字。**必须是别人给的**，玩家不能给自己起。

**暴露程度与身份记录的区别（重要）**：
- 暴露程度上升 = 你越来越藏不住；
- 身份记录变化 = 你在档案里变成了另一种人。
- 这两件事不同：你可能被通缉但暂时没人找到你，也可能身份干净但刚出手闪了一下。

### 角色（每个核心角色一条记录，key 用真名）

- /角色/{真名}/故事线进度 —— 他走到哪一步了。文字，写明当前处在哪个阶段。
- /角色/{真名}/位阶传闻 —— 圈内以为他是什么水平。只能是：不入流 / 中游 / 高位 / 传闻极强 / 深不可测。
- /角色/{真名}/位阶真实 —— 他实际是什么水平。取值同上。
- /角色/{真名}/玩家已知程度 —— 玩家对他真实水平的掌握程度。只能是：未知 / 有传闻 / 已确认。
- /角色/{真名}/与玩家的账 —— 两人之间的人情与过节。字符串数组。例：["欠他一次人情","他失信于我"]。**用标签，不要用好感度数。**
- /角色/{真名}/被掌握的底牌 —— 玩家已经掌握了他哪些底牌。字符串数组。
- /角色/{真名}/圈内代号 —— 他的圈内代号。文字。
- /角色/{真名}/已接触 —— 是否已经和玩家打过交道。true / false。

**位阶的三个字段必须分别判断，不能混用**：
- 位阶传闻是"别人怎么说"，可以不准、可以被故意传歪；
- 位阶真实是"他到底多强"，通常不变；
- 玩家已知程度是"玩家知道多少"，只有当玩家真的验证过、或拿到可靠情报时才提升。
- **玩家已知程度没提升时，即使位阶真实很高，叙事里也不能让玩家"看出来"。**

### 世界

- /世界/日期 —— 游戏内日期。文字。玩家主动跳过时间时推进。
- /世界/事件线 —— 已发生的关键事件。字符串数组。**只记结果，不记过程。**
- /世界/势力状态 —— 各方势力当前状况。四个字段：管理局 / 家族 / 散人网 / 没落旧家。各一句话。
- /世界/当前引力源 —— 现在有谁在找玩家。字符串数组。例：["管理局在查觉醒记录","散人网想接触玩家"]。
- /世界/结局进度 —— 整体推进到哪个阶段。文字。

**事件线的写法要求**：
- 记"结果"不记"过程"——写"某据点被清掉了"，不写"某某和某某在某地打了一架又跑了"；
- 一条不超过一句话；
- 不要记录玩家已经知道、但世界层面并无变化的事情。

## 什么时候该更新什么

- 玩家用了能力 → 暴露程度上升；内在损耗上升；若被看见，可能改身份记录。
- 玩家休息、过了一段时间 → 内在损耗下降；暴露程度下降；日期可能推进。
- 和某个角色产生人情或过节 → 该角色的"与玩家的账"。
- 玩家验证了某人的真实水平 → 该角色"玩家已知程度"提升；"被掌握的底牌"追加。
- 某角色的剧情线往前走了 → 该角色"故事线进度"。
- 世界层面出了事 → 事件线追加；相关势力状态改写。
- 有人开始找玩家 → 当前引力源追加。
- 玩家第一次遇见某角色 → 用 add 写入该角色的完整记录，已接触设为 true。

## 不要做的事

- 不要重写没有变化的字段；
- 不要把整套变量重新输出一遍；
- 不要在变量里写剧情描写或对话；
- 不要自己发明新的位阶等级或枚举值；
- 不要写 /世界/变量结构版本 —— 这个字段由脚本管理。
