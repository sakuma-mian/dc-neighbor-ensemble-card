## 1. 预设体检结论（260821稳定版max ↔ 本卡对接点）

对 `D:\酒馆\绘绘绘绘绘~260821稳定版max.json` 全文（3871 行：prompts / prompt_order / 酒馆助手脚本 / 正则）逐节核对，与本卡相关的结论：

1. **叙事人格是包装层**：预设把模型包成「讲述者上杉绘梨衣」，故事正文里的角色依角色卡独立行动；`main_task` 明确优先级 **角色卡/世界书/聊天历史事实 > 预设档位 > 默认补全**——本卡世界书是事实权威，无冲突。
2. **通用思维链已是"无原著"形态**：`thinking_chain_universal`（默认开启）六步 = 世界观自洽 → 主角行踪回顾 → 故事进度定位 → 因果链 → 冲突校验 → 写作准备；步.1 用「铺垫期/上升期/高潮」定位，**不引用任何原著**。它引用的"记忆/纪要"素材默认指向备忘卡（erii_memo）——本卡按 DEC-013 关备忘，此缺口由 **N0 状态对齐** 补上（见 §4）。
3. **变量无碰撞**：预设自有的档位变量（game_mode、length_contract、dialogue_control 等约 80 个）经 `erii_var_init` 每轮清零重建，命名空间与本卡 `stat_data` 六容器零交集。
4. **输出装配序固定**：思维链(erii_draft) → 场景卡(关) → `<content>` 正文 → 与此同时(<meanwhile>) → paper(关) → 小剧场(关) → 备忘(关，DEC-013) → 悄悄话(关) → 选项栏(开) → 【状态更新】。本卡 `<UpdateVariable>` 块落在最末，与【状态更新】标记对位（见 N0 第四节）。
5. **正则只认 erii 系标签**：预设的 promptOnly 清理正则覆盖 `<erii_draft>/<erii_theater>/<erii_memo>/<meanwhile>/<options>/<paper>` 等，**不认识 `<UpdateVariable>`**——历史里的变量块要靠 MVU 框架解析＋R3 卡侧正则做渲染隐藏与提示词清理（见 §7）。
6. **预设默认档与本卡裁定的偏差**（需驱动开卡时手动核对，详见 §6）：备忘默认**开**（本卡要关）、NSFW 默认**强化**（DEC-007 要标准）、龙族世界默认**开**（本卡建议关）、台词密度默认**少**（群像卡建议匀）。
7. **性能参数**：max_tokens 30000、context 2M、Gemini 双模型（DEC-011）均可容纳 N0 状态块的全表序列化成本（§8 风险 1）。

- **为什么 INC 用常驻而不是关键词绿灯**：初遇、群像、保密是"每一轮都要在场的纪律"，关键词无法可靠命中（"初遇"二字未必出现在消息里）；条目自身内置生效条件（N3 明写"仅当…时执行"），模型按条件跳过，成本可控。
- **为什么 N4 用 R2 翻开关而不是绿灯**：与秘密词条同机制（DEC-010 门控家族），R2 每轮从 `关系`/`任务` 容器幂等推导 disable 值，新聊天/回溯自动复位。
- **契约增量提案（待驱动确认）**：设计契约 §② 未列"剧情侧状态注入"，但 INC-1 职责（"逐条引用当前已揭示迷雾格"）要求剧情模型能看到迷雾**状态**（不含秘密内容）。N0 用框架宏 `{{format_message_variable::stat_data}}` 承担，与变量层 `[mvu_update]变量列表` 同宏同包装。单模型模式下两处重复注入同一状态（可接受；组装门可测合并）。

## 5. INC/MOD 与既有层的分工边界

- **角色层主词条**：表面行为锚点（护眼、贴创可贴、耳机、乌鸦耳坠）——秘密的"果"不在主词条，成因锁在 R2 门控的秘密词条（ENT-H1..N4）。

- **INC-2**：调度规则通用化；角色个体在线规律/生活轨迹只在各主词条，INC-2 不复制。
- **INC-3**：路由表是"轴→角色"的聚合视图，与各主词条"与主控：…相遇概率大"行互为引用不重复；识别引信清单只在主词条。
- **MOD-A/B**：框架文本；逐角色里程碑场景随任务层（DEC-203）与彩蛋层（DEC-204）落盘后补齐到对应词条。

## 7. 输出协议对齐与 R3 附加要求

- `<UpdateVariable>` 永远是回复最后一个块（变量层规则），与预设装配序末位的【状态更新】标记对位；单/双模型归属判定写在 N0 四节（模型按"`[mvu_update]变量输出格式`词条是否在上下文"自判）。
- **R3 增补（进 R3 门任务清单）**：除渲染层隐藏外，增加一条 **promptOnly 正则**从提示词历史中剥离 `<UpdateVariable>…</UpdateVariable>`（预设自带清理正则不认识该标签；MVU 框架解析读原始楼层消息，不受影响）。
- 开场白/示例对话（组装门）：开场白不写任何 erii 系标签与变量块（DEC-005 不伪造初始化）；示例对话按契约 §① 示范打岔反应。

## 8. 风险登记与复议项

1. **N0 常驻成本**：状态全表序列化约 2-3K 字/轮（105 迷雾单元+五容器）。Gemini 3.1 Pro 上下文无压力；ACC-005 用真实 tokenizer 复核，并测试"未揭示格折叠输出"的省 token 变体（框架宏行为决定，不预设）。
2. **事实 ID 的话题暴露面**：迷雾表把 `Q.霸凌` 这类**话题编号**暴露给剧情模型（不含内容）。这是设计要的——模型"知道有事、不知详情、按 INC-1 演回避"；但**严禁**把该表接入任何玩家可见 UI（display_data 维持留空，DEC 排除项），否则 21 格全量剧透。
3. **备忘卡复议**（DEC-013 预留）：若实测连续性不足要重开备忘，N0 一节"无原著模式"已兜底其"锚点/蝴蝶效应"字段语义（只相对本卡已确立事实）；届时二节"记忆素材约定"需同步改写。
4. **预设版本漂移**：DEC-013 锁定 260821；预设升级时重跑本 README §1/§6 两表对照（检查点：通用思维链文本、输出装配序、erii_var_init 变量清单、正则清单）。
5. **平行会话**：本层落盘前后 authority 可能被并行修改（前科：DEC-106/107）；编号 ENT-050..054 / DEC-026 已扫占用，冲突时以 authority 为准重排。
