## 2. 门控契约（重迷雾·与 R2 迷雾门卫脚本的接口）

- **主词条**：普通绿灯，只由聊天消息中的角色名/网名激活；不携带任何秘密。
- **秘密词条**：绿灯 + `disable` 由 R2 控制。默认 `disable=true`（秘密不进上下文）；对应事实在 `迷雾` 容器中**任一知情者格**（知情者≠事实本人）变为「已揭示」或「误信已纠正」后（DEC-025 口径），R2 在 `mag_variable_update_ended` 中把该词条 `disable=false`，此后该词条随角色名关键词正常注入（已揭示的事实需要长期在场，驱动角色行为更新）。
- **幂等**：R2 每轮从当前聊天状态全量推导全部秘密词条的 disable 值——新开聊天/回溯分支自动复位，不串档。
- **写作纪律**：秘密词条内容只包含"已揭示事实 + 行为更新"；未揭示时的保密行为一律写在主词条保密纪律行与 INC-1（CoT 增量）里，不重复。

## 4. 预算自检

- 常驻：起源层（~450 字）+ C0 总纲（592 字）
- 典型单轮：起源 + 总纲 + 1-2 城区（关键词）+ 1-3 主词条（提及的角色）+ 已揭示秘密词条（角色名命中才注入）≈ 1500-3000 字
- 极端（五人全员在场+全部揭示）：约 6000-7000 字 ≈ 3600-4200 token——Gemini 上下文下无压力，仍符合城市层 README §4 的预算纪律
- 精确 token 在 ACC-005 用真实 tokenizer 复核
