## 条目 ENT-V02（内容源）

- **条目名**：`[mvu_update]变量更新规则`
- **策略**：🟢 Conditional（关键词：更新、变化、状态、变量）
- **投递位置**：`position=1`（After Char Defs）
- **预算**：约 1,100 字（估算）
- **内容（模型可见）**：

```text
【变量更新规则】

一、输出纪律（硬性）
- 所有变量写入必须放在 `<UpdateVariable>` 块内，由 `<analysis>` 与 `<JSONPatch>` 两段构成。
- `<analysis>` 中每一行都描述正文里的一个实际变化，且每一行都必须对应至少一个 patch；不得分析中提到变化而 patch 缺失，也不得写出正文里没有发生的变化。
- 只使用四种操作：`add`、`replace`、`remove`、`move`。禁止使用 `delta`、`insert` 或其他操作。
- `replace` 要求目标路径已经存在；若路径不存在，必须先用 `add` 写入完整对象，再对其子字段使用 `replace`。
- **本轮没有任何状态变化时，不要输出 `<UpdateVariable>` 块。** 宁少勿错。

二、写入者归属
- 所有变量由剧情链写入；脚本只做确定性推导，不参与写状态。
- 每个字段只有一个写入者，禁止同一字段被多处同时改写。

三、各字段的更新时机

1. `/世界/日期`、`/世界/时段`
   - 正文明确推进了时间就更新；未推进不动。
   - 时段取值共八档：早间 / 上午 / 午间 / 下午 / 傍晚 / 晚间 / 深夜 / 凌晨。

2. `/世界/区`、`/世界/场所`
   - 角色发生物理移动就更新。
   - `区` 只取四个行政区之一：江北 / 江南 / 新区 / 月石；未确定时用「未定」。
   - 具体地点一律写进 `/世界/场所`（例如「深港·未登记层」「南江大学」「滨江人文带」「月石港区」——这些都不是区名，不要写进 `区`）。

3. `/世界/面纱`（完好 → 有裂痕 → 局部暴露）
   - **只降不升**。只有出现“普通人确知或高度怀疑异能存在”的情节时才下调一档；任何情况都不得回升。

4. `/主控/姓名`、`/主控/来历`、`/主控/异能倾向`、`/主控/异能`
   - 前三项由开局问卷经正常剧情写入。`异能倾向` 记录玩家的期望方向，尚未觉醒时也保留。
   - `异能` 在觉醒场景中定型后不再随意改动；改写须有明确的剧情理由（二次觉醒、能力变异等）。

5. `/主控/觉醒阶段`（未觉醒 / 初醒 / 掌控 / 过载）
   - 触发觉醒 → 初醒；能稳定调用 → 掌控；过载结束后回落一档，并留下后遗症。

6. `/主控/代价`（0–100，反噬累积）
   - **主动型能力**（需要意图与专注才能发动）：初醒阶段每次 +8～+15；掌控阶段每次 +3～+8。
   - **常驻型能力**（不需要发动、持续或半自动生效，如「留白」「解析」）：不按次计，改为按**事件**计——每次因该能力发生了对剧情有影响的结果（有人因此没记住她、或她看穿了关键破绽）计 +3～+8；若只是背景性的、没有产生后果的感知，不计。
   - **进入过载**一次 +25～+40。
   - 充分休息且未使用能力的一日，自然恢复 −5。
   - 档位含义：0–20 轻微不适；21–50 明显影响行动；51–80 能力开始难以控制、身体明显受损；81–100 危险，不得再主动使用能力。

7. `/主控/暴露度`（0–100）
   - 在普通人面前公开使用能力：+10～+25（按目击人数与场景公开程度取高取低）。
   - 被动暴露（被知情者盯上、留下痕迹）：+3～+8。
   - 长期无新事件：每三日 −2。
   - 档位含义：0–20 无人注意；21–50 被知情者盯上；51–80 组织主动接触；81–100 被优先处理。

8. `/角色/<角色名>/*`
   - `已遇`：线上或线下第一次见面即置 true，只置一次。
   - `现实身份已知`：玩家确认了对方的网名与真人的对应关系时置 true。
   - `已知为觉醒者`：玩家确认对方是觉醒者时置 true。
   - `好感`：单次事件 ±3～±10，重大事件可到 ±15。
   - `关系阶段`（陌生人 / 认识 / 熟悉 / 信任 / 亲密 / 破裂）：**需要同时满足数值门槛与剧情里程碑**，不得只凭数值跳级。
     · 陌生 → 认识：`已遇` 为 true 即可。
     · 认识 → 熟悉：好感 ≥ 20。
     · 熟悉 → 信任：好感 ≥ 45，且已发生过一次该角色的“关键相处事件”（见各角色词条的相处要点）。
     · 信任 → 亲密：好感 ≥ 70，且已达成该角色专属的里程碑。
     · 破裂：任何阶段都可由一次重大事件直接触发。
   - 秘密与背景的浮出：某个角色的 `关系阶段` 进入「信任」及以上后，其尚未透露的背景会**经由具体场景自然带出**（一件旧物、一次偶遇、一句失口），不得集中交代、不得主动倒出。
   - `其他信息`：会影响后续的临时状态（伤势、欠下的人情、约好的时间）。

9. `/事件/进行中`
   - 新线索或任务出现时用 `add /事件/进行中/-` 追加一项，每项含 `标题`（文本）与 `状态`（未接 / 进行中 / 完成 / 失败）。
   - 上限 5 条。已有事件完结且确定不再有后续影响时，用 `remove` 删除**该事件对应的数组项**（按标题确认要删的是哪一项）。
   - 不要用事件容器记录流水账。

四、取值纪律
- 数值字段写数字（不加引号），布尔字段写 true / false，枚举字段必须写规定的取值之一。
- 写错取值或类型会导致该条写入不被采纳：**宁可少写一条，也不要写一个近似值**。不确定时保留原值不动。
- 不要写入与本轮正文无关的字段（例如玩家在图书馆读书，就不要更新暴露度）。
- 不要新增本规则未列出的顶层容器或路径。
```

## 作者须知（**不注入模型**，仅供维护）

1. **为什么没有“可照抄示例”**：完整可复制的输出示例会让模型逐字搬运，因此本条目只给结构与约束。任何新增示例都必须是**占位符形式**（如 `"<新时段>"`），不得出现完整可用的取值组合。
2. **非法值的行为**：schema（`schema/zod_schema.js`）不对非法值做兜底，验证失败会让该条 patch 不被采纳、**原值保留**。这是有意设计——**绝不要**在 schema 层加 `.catch()`，那会把“校验失败”伪装成“悄悄改成默认值”（详见 schema 文件头注释）。
3. **常驻型能力的判定**：花奈「留白」与诺薇拉「解析」没有“发动瞬间”，因此按事件计代价（本文件 §6）。若实机发现模型仍按次计，再考虑改为脚本侧推导。
4. **关系阶段双条件**：数值只是门槛，里程碑在各角色词条（`P1`～`P5` 的「相处要点」）中定义，两者缺一不可。
