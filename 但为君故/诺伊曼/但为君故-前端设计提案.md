# 《但为君故 · 沉吟至今》前端设计提案

设计方向：**夜航档案 · 江雾留痕**。保留已有青冷识别色，借鉴《鸣潮》官网的影像尺度、纵向人物构图、疏朗排版与克制的导航，使南江市与五个人成为视觉主体。

本次交付为设计提案及布局示意，未修改原仓库，未制作可导入脚本，也未进行 SillyTavern 实机验收。开场页纳入提案；现有实现的状态栏与群像档案是优先改造对象。

## 1. 浏览依据与判断

仓库读取基线：`d0699d83466ad396f914fc32f22fc70d93ed941e`，2026-09-13 拉取。

- 阅读了目标目录的决策记录、设计契约、卡字段、世界观与场所设定、角色内容、初始变量、设计令牌，并查看现有预览与渲染实现。
- 浏览器实际查看《鸣潮》官网首页、资讯、共鸣者和世界板块。资讯页是深灰背景、哑金细线、宽幅图文分区；共鸣者板块以窄长立绘队列和大面积留白组织人物；世界板块以横向大景图、地点名和短简介组织探索。
- 仓库 `tokens.md` 记录的青色像素占比并非本轮复测证据，不把它当作鸣潮整个界面的主色结论。官网运行时样式本轮可以获取，旧文档中“无法取得真实样式”的描述不代表本轮结果。
- 保留 `DEC-062` 的青冷身份；这份提案扩展视觉与交互，不覆盖原决策。官网的金色不必全量搬入本项目。

现有界面的长处是状态模型明确、双身份条件已有基础、零网络依赖。主要视觉问题是五张等权状态卡把每轮面板拉得很长，细网格和边框占用注意力，人物以字牌承载，城市几乎没有出场。改进重点是画面与内容的比例。

## 2. 产品中心

玩家从普通人的视角进入南江，在日常交往中遇见五个人，逐渐发现现实身份与异常的一面。界面围绕三件事组织：**我在哪里、我付出了什么、我究竟认识她多少。**

整体是玩家的随身记录。避免把全部界面包装成“基金会内部终端”：玩家开局尚不知基金会存在，也没有获得查阅机密的身份。

保留关系与风险的不同含义：好感不是攻略完成度，代价不是蓝量，过载不是奖励性大招，面纱下降也不意味着解锁了更多地图。

## 3. 四个界面

| 界面 | 玩家任务 | 视觉焦点 | 数据与交付边界 |
|---|---|---|---|
| 初到南江 | 描述自己，开始故事 | 江北小巷、窗与手机消息 | 开局问卷的视觉包装；信息通过真实玩家消息进入剧情链 |
| 此刻 | 每轮快速查看地点、风险和关系变化 | 紧凑文字、两条细计量尺 | 对应现有状态栏，优先实施 |
| 人物 | 浏览某个人的已知信息 | 一位人物主视觉、五人选择列 | 对应现有群像档案，优先实施 |
| 南江 | 理解公开地点与手头线索 | 城区景图、地点索引 | 扩展页；公共地理可读，隐秘内容需要额外发现记录 |

深夜频道可在开场和线索详情中出现。当前没有持久群聊记录结构，不把它做成会自行生成消息的完整聊天应用。

### 3.1 初到南江：门外第一盏路灯

桌面布局：约六成画面呈现开场中的江北小巷；另一侧为四项轻量问卷。标题“但为君故”用较大的中文宋体，“沉吟至今”作为短副题。

建议新写入口文案：**“你来到南江，总有一个理由。”** 这是界面提案文案，不是原文引用。

四项输入严格对应现有开场：称呼、原本在哪里做什么、来南江的理由、希望发生的异常。允许自然语言回答与留空，不增加属性分配、职业天赋或初始能力购买。

流程：填写 → “看看我的开场” → 查看将发送的完整文字 → 返回修改或确认发送。自动发送失败时保留草稿与可复制正文。最终能力在剧情觉醒中形成；点按钮不能直接给主控写入能力或觉醒阶段。

手机端：先显示短景图、标题与一句引导，随后单列问卷。正文仍使用酒馆正常消息流；提交完成后退出开场流程。

画面不预先交代第九条、基金会、地下典籍等秘密。那条隧道失踪十一分钟的传闻来自原开场，可以作为悬念出现。

### 3.2 此刻：一眼读完

收起态只保留时间地点、觉醒阶段、面纱、代价、暴露度与“人物／线索”入口。桌面目标高度约 96–132px，窄屏约 150–190px；这是布局目标，长地名与放大字体时允许增高。

布局示意（数值均为演示，不是实际存档）：

```text
纪年第 3 日 · 傍晚       江北 / 市图书馆新馆       [展开]
初醒        面纱：有裂痕
代价 34/100 · 明显 ━━━━━      暴露 14/100 · 轻微 ━━
人物 5      进行中线索 2
```

展开态增加五人紧凑行与最多五条进行中事件。人物行显示网名、关系阶段、好感有符号数值、身份标记。相较现有五张大卡，关系摘要改为连续列表；选中一人进入独立档案。

好感条以 0 为中点，负向向左、正向向右；0 显示“0”，不把 -100～100 映射后得出的 50% 视觉长度呈现为“已经完成一半”。关系阶段仍读取真实字段，不从好感推算。

代价与暴露度保留既有分段：0–20 轻微、21–50 明显、51–80 严重、81–100 危险。明确写文字，并配形状或图标。面纱使用完整枚举：完好／有裂痕／局部暴露。

同聊天相邻楼层有可靠快照时，才可标出“本轮 +8”；没有前态就只显示当前数值。前端不负责休息减值或任何结算。

### 3.3 人物：视觉主场

桌面构图：左侧约 18% 是五人的纵向选择列，中间约 45% 为当前人物画面，右侧约 37% 放身份、关系与已知记事。边栏用网名，进入档案时保留选择位置。移动端为横向可滚动人物选择条、短幅人物画面、单列档案。

名字比字段标签大，人物画面比面板更有分量。真名未知时让网名成为主标题；真名揭晓后主标题换成真名，网名留作副标题。避免在未揭晓时用姓氏占位字、图片描述或标题提示泄露真名。

右侧三个区：

1. **我们之间**：已遇、关系阶段、好感。
2. **已知身份**：现实身份与觉醒者身份分别显示，互不代替。
3. **记事**：当前 `其他信息` 原样安全显示。它是现况备忘，不是有时间戳的永久回忆库。

角色绘制方向（遵守原人设外貌，以下仅为构图提案）：

| 人物 | 已有能力 | 构图与环境建议 |
|---|---|---|
| 藤原花奈／佐久间眠 | 留白，常驻型 | 冷白窗光、克制站姿、较多留白；不把她绘成能够抹去照片或文字的人 |
| 顾清寒／珍惜才配拥有 | 威压，主动型 | 绿色高马尾、运动感站姿、街角侧光；不使用可造成实质破坏的气场特效 |
| 鱼沉秋／cojack | 缝，主动型 | 室内近景与安静的手部动作；细线只作为关系构图隐喻 |
| 楚羽笙／楚楚的笙_unofficial | 回声，主动型 | 耳机与夜间屏幕光；短暂声纹是可选装饰，不冒充真实音频 |
| 诺薇拉／冯诺依曼 | 解析，常驻型 | 桌面资料、错位线框与停顿感；避免万能扫描器或未来预知式画面 |

**揭晓逻辑必须比立绘更先设计。**

| 已有字段 | 足以显示 | 不足以证明 |
|---|---|---|
| 已遇 | 曾线下相遇 | 此刻在场、当前坐标、知道真名 |
| 现实身份已知 | 真名及获准显示的现实身份 | 知道她是觉醒者或其能力细节 |
| 已知为觉醒者 | 觉醒者身份标记 | 知道能力名、完整边界、反噬、登记档案 |
| 其他信息 | 当前记事 | 不可更改的事件历史、双人关系知识网 |

能力详情、登记状态、角色间秘密，不因“觉醒者已知”为真而自动全部展示。第一版优先只展示现有字段能够证明的内容；若要逐条解锁档案，先增加独立的“已知条目”契约，再建设相应栏目。

未获知内容不生成到可访问 DOM，不只加模糊滤镜；图片 alt、工具提示和读屏文本也遵循相同规则。这保证的是游玩界面的信息纪律，不宣称卡包源文件本身具备保密能力。

### 3.4 南江：景图与索引

四个城区入口：江北、江南、新区、月石。南江大学是江北场所，深港是地下场所，不升级为并列行政区。

沿用官网世界板块“大景图＋地名＋短简介”的节奏：江北突出大学与民生日常，江南突出天际线与老码头并置，新区突出通勤与夜市，月石突出港口和班次。使用原创城市图，不画成鸣潮的幻想遗迹。

首版可做公开城市索引，并标出 `世界/区`、`世界/场所`。当前结构没有已探索地点、可达路线、角色实时位置或已发现秘密记录，因此不能绘制“真实可用”的任务导航地图、探索百分比或全部隐秘据点。

场景主视觉可随现有八档时段调整亮度层次；没有天气字段，就不声称画面雨雪代表当前天气。1999／2029 属世界设定，当前“纪年第N日”不足以计算准确复审倒计时。

## 4. 视觉规范

| 层 | 方案 |
|---|---|
| 背景 | 继承 `#060E12`、面板 `#0B161C`；大区域用平静暗面 |
| 正文 | 冷白 `#E4F1F4`，次要字 `#9FBAC2` |
| 识别色 | 继承青 `#5FD4E0`，集中于选中标记、导航和细线 |
| 状态 | 继承安全绿 `#74C08A`、注意黄 `#D9A93C`、危险红 `#E06055`，同时给出文字 |
| 字体 | 开场与人物标题使用中文宋体回退栈；正文使用现有系统黑体；数字等宽对齐 |
| 字阶 | 大界面标题 40–64px，人物标题 28–40px；正文 14–16px；辅助 12px；小状态栏单独控制密度 |
| 几何 | 以直边和 1px 分隔为主；切角只留给少数主要按钮或容器 |
| 纹理 | 阅读与状态区域去掉重复网格；场景装饰只在空白边缘低对比出现 |
| 母题 | 一条原创的南江水岸线贯穿标题分隔、人物选择轨道与地点页；不复制官网标志性波纹图形 |

“江雾”由场景纵深与色阶形成，不靠全屏模糊。“留痕”由已知信息与关系变化形成，不靠不断扫描的装饰动画。世界面纱状态若被映射为一枚逐渐断裂的线形标记，也只作为全局状态提示，不能让整张人物立绘同步解锁。

## 5. 动效与声音

- 人物切换：约 220ms 的短距离位移与淡入，文字稳定，不让整页闪白。
- 档案展开：约 180ms；面板从入口附近出现，关闭后焦点返回入口。
- 数值变化：约 150ms，并同时显示变化后的文字。
- 身份揭晓：只对真实发生的状态变化给一次短过渡；单纯打开面板不重复播放。
- 遵循减少动态效果偏好；关闭位移与装饰过渡后所有内容照常可读。
- 默认静音，首版无音频依赖。若将来加入环境音，需明确播放器与授权素材，不自动播放。

## 6. 交互与接入约束

保持原生 HTML/CSS/JS 与现有卡结构，优先修改维护源 `frontend/tokens.md`、`preview.html`、`render.js`。可先做独立离线样张；正式接入才核对实际 Tavern Helper、MVU 版本和宿主事件。

状态所有权分为：正式 `stat_data`、开局草稿、当前标签与展开状态、派生展示值。展示层只读正式状态；草稿不能直接覆盖它。切换聊天时清理上一聊天的草稿和界面引用。

状态栏随目标消息楼层刷新；档案默认展示当前查看范围的数据，并显示其时点。切换 swipe、消息编辑和聊天切换后不能保留另一个分支的人物揭晓状态。

读取失败时显示“状态暂不可用”与重试，保留能够确定的最后数据并标识旧状态；不可用时不能伪造“面纱完好、代价0”。缺立绘时用网名与中性构图占位，不调用随机远程图片。

浮层需要 Escape 关闭、焦点管理和明确返回按钮。宽度依据消息容器判断；覆盖 320、390、680、1080px 容器及 200% 缩放。全部模型与用户文本通过安全文本方式渲染。

## 7. 素材和实施顺序

第一批素材：五人同画风人物图，各自适合裁成头像的安全区域；一幅江北开场场景；必要的本地图标与许可信息。地点页列为后续，再补四区景图。正式立绘应先按 P1–P5 的完整外貌锚点做人物表；本轮未生成或获取这些素材。

优先顺序：

1. 压缩状态栏，落实好感零点与身份展示条件。
2. 做一位人物完整档案样张，再扩展五人；保持选中态与移动端手势、键盘行为一致。
3. 包装现有开局问卷，验收预览、修改、发送与失败保留。
4. 加入公开城市索引；知识记录结构就绪后再扩展秘密条目。

交付验收：桌面与窄屏可读、未知身份不穿帮、状态刷新不串聊天、面板打开不改变量、输入失败可恢复。运行时验收必须使用最终构建的同一版本，在真实 SillyTavern 中测试；离线样张通过不等于宿主通过。
